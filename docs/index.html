Wind turbine O&M reliability from status and alarm logs

What the monthly O&M report and the meeting with the service provider are about, computed from the turbines' own event logs: which codes and components cost the most downtime and energy, MTBF and MTTR per turbine and component, whether reliability is getting better or worse (Weibull, Crow-AMSAA), bad-actor turbines, repeat failures, alarm cascades, automatic resets against interventions and service response time. Three open wind farms with two manufacturers: Kelmarsh (6 x Senvion MM92, 2016-2021), Penmanshiel (14 x Senvion MM82, 2016-2024) and Hill of Towie (21 x Siemens SWT-2.3-VS-82, 2016-2026). Code and method: github.com/kwwaleszczynski-del/wind-om-reliability.

1. Pareto of downtime

Stop hours attributed to the first-up event (overlapping stops are never counted twice), split at calendar boundaries. All stop categories: faults, maintenance, grid, curtailment, environment. Lost energy is available for the years with 10-minute SCADA.

2. Failure timeline

Every failure (forced-outage stop episode, fleet-wide common causes excluded), one row per turbine. Size: restore time; colour: component; diamonds: repeats of the same code within 7 days after restart. Drag to zoom, hover for the code.

3. Is reliability improving?

Crow-AMSAA (Duane plot)

Failures per turbine-year

Calendar years in UTC; partial first and last years.

4. Bad actors

Jack-knife diagram of status codes

Knights' jack-knife: failures against mean time to restore (log axes). Dashed: mean failures per code and the overall MTTR. Upper right: acute + chronic. Grey curves: equal downtime.

MTBF and MTTR per turbine

MTBF = operating hours / failures with a 90 % chi-square interval; MTTR = mean time to restore (first stop to restart, waiting included). Highlighted: more failures than the fleet rate explains (Poisson test, false discovery rate 5 %).

5. Repeats, cascades and how failures end

Repeat failures (same code within 7 days)

Chance: the repeat rate the code would show from its own frequency alone (Poisson). Far above chance = resets without a fix.

Alarm cascades (primary -> secondary within 2 min)

Confidence: share of the primary's episodes that bring the secondary along; lift: how much more often than by chance.

How failures were restored

Components: failures per turbine-year and MTTR

6. Logs against SCADA

Do the logged stops match what the 10-minute signals show (the parked-rotor signature of wind-downtime-availability)? The clock check shifts the log against SCADA: a peak away from zero is a time-zone or daylight-saving error.

Clock check

Stop hours per turbine and month

Lost energy: expected power from the running neighbours (method of wind-downtime-availability), shortfall capped by the logged stop fraction of each 10-minute interval. Greenbyte: the operator platform's own lost production to downtime (Kelmarsh, Penmanshiel). Hill of Towie: shutdown hours computed by the operator from SCADA and its own logs.

7. Use it on your own logs

Any export with turbine, start, end (or duration) and code - a YAML file says which column is which, the time zone of the timestamps (Europe/Warsaw with both clock changes handled) and how categories translate; a CSV maps codes to components and to on-site / remote roles. Output: a monthly KPI pack in Excel and HTML. Example packs: Penmanshiel, November 2020, Kelmarsh, March 2021, Hill of Towie, November 2021 (Excel versions next to them).

pip install "wind-om-reliability[scada] @ git+https://github.com/kwwaleszczynski-del/wind-om-reliability"
python -m wind_om template alarms.csv --config my_oem.yaml --out my_codes.csv      # codes to map
python -m wind_om report alarms.csv --config my_oem.yaml --mapping my_codes.csv \
       --month 2026-09 --tz Europe/Warsaw --out kpi/                             # + --scada for lost MWh
Data: Kelmarsh and Penmanshiel wind farm data (Cubico Sustainable Investments, Zenodo, CC BY 4.0); Hill of Towie open dataset v2.1.0 (RES, Zenodo 10.5281/zenodo.22662930, CC BY 4.0). Code-to-component mappings were written from the public code texts and inferred from SCADA where no text exists; they are working assumptions, not OEM documentation. Contract definitions (what counts as a failure, response-time clocks) differ and should be checked against the actual contract.
